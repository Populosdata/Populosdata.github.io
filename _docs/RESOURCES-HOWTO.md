# How Resources articles work

`/resources/` is generated by `_tools/build_resources.py` from `_resources/manifest.json`. Don't edit `resources/index.html` or the article pages by hand, because the next build will overwrite them.

## Files
- `_resources/manifest.json` lists every article: `slug`, `title`, `excerpt`, `category` (Guides, Case Studies or Trends), `readMinutes`, `order` (the planned order, 1 = first), `vetted`, `releasedOn` (empty until release, then the day it went out; set by the build), `image` (null means the plain branded cover) and `status` (`scheduled` or `published`, set by the build).
- `_unreleased/<slug>.html` holds each article's body as an HTML fragment. Jekyll does not serve this folder, but **the repo is public, so these files are readable on GitHub**.
- `resources/index.html` and `resources/<slug>.html` are generated pages. `resources/resources.css` is the shared stylesheet.
- `.github/workflows/release-resources.yml` is the release workflow (see below).
- `_docs/PUBLISH-DAY-CHECKLIST.md` lists the claims El confirms before setting `vetted` to `true`.

## When an article goes live
Articles have no fixed dates. The workflow runs at 05:15 UTC on Tuesdays and Thursdays and releases **at most one** article per run: the unreleased article with the lowest `order`, and only if `vetted` is `true`. If that article is not vetted, nothing is released, and a later vetted article doesn't jump ahead. A date alone never releases anything. The workflow can also be run by hand from the Actions tab, with a **dry_run** option that changes nothing.

When it releases an article, the workflow:
1. stamps `releasedOn` with that day's date (UTC), which is the only date ever shown publicly;
2. writes `resources/<slug>.html`, with that date on the page and in its metadata;
3. switches the article's card from "Coming soon" to "Read", showing that date;
4. adds the page to `sitemap.xml`, with that date as `lastmod`;
5. sets the article's `status` to `published`;
6. commits to `main`, then asks GitHub Pages to rebuild.

Unreleased articles show "Coming soon" and no date anywhere.

It touches nothing else. If the manifest is invalid, or anything else is wrong, the run fails and is marked red in Actions.

## Adding a new article (from a pasted article)
1. Branch from `origin/main`.
2. Save the body as `_unreleased/<slug>.html`, using `<h2>`, `<h3>`, `<p>` and `<ul>`. Don't add a title or an `<h1>`; the page template adds those.
3. Add an entry to `_resources/manifest.json` with the next `order` number, `"vetted": false`, `"releasedOn": null` and `"status": "scheduled"`.
4. Run `python _tools/build_resources.py`. Then serve the site locally (`python -m http.server 8000`) and check `/resources/`.
5. Commit only the files you changed, by explicit path, and open a PR. Only El sets `vetted` to `true`.

## Content rules
- Marketing copy only. No constants, weights, thresholds, window lengths or model inputs.
- Don't add claims that haven't been approved.
- Don't say or imply that static and digital are measured the same way.
- No em dashes.
